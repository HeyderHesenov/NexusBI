# ── Server defaults the migrations applied and the models never declared (52)
#
# Direction matters: the DATABASE is the more constrained side here. These
# columns were added NOT NULL by a migration, which has to supply a
# server_default to backfill the rows already in the table; the model kept only
# a Python-side default=, which is all the ORM needs.
#
# The cost is real but narrow: a schema built from the models -- which is what
# tests/conftest.py does -- has no default on these columns, so an INSERT that
# omits one fails there and succeeds in production. Nothing in the app inserts
# by raw SQL today, so nothing hits it.
#
# Fixing these means adding server_default= to 52 columns across 24 model files.
# That is its own change, deliberately not bundled with the guard that found it.

# ── brand_configs.user_id: one uniqueness rule expressed two ways (3)
#
# The database enforces uniqueness with a UNIQUE CONSTRAINT
# (brand_configs_user_id_key) and additionally carries a plain index
# (ix_brand_configs_user_id). The model asks for a single UNIQUE INDEX of that
# name. Uniqueness holds either way -- verified against pg_constraint -- so this
# is representational, plus one redundant index the database does not need.
#
# Worth cleaning up in a migration that drops the plain index and lets the
# model's unique index be the one rule. Not urgent, and not this change.

add_index:brand_configs.ix_brand_configs_user_id
remove_constraint:brand_configs.brand_configs_user_id_key
remove_index:brand_configs.ix_brand_configs_user_id
